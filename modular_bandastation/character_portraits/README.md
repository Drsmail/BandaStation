## Подготовка для F5

1. Реализовать библиотеку по контракту выше, подготовить сборку и установить DLL/SO по пути из character_portrait_library(). Готового build.ps1 библиотеки в этой ветке нет. Перед установкой остановить игру.

2. Для существующей БД BandaStation версии 1.3 применить SQL/bandastation/updates/1.3-1.4.sql. Это единственная миграция портретов; имена таблиц соответствуют текущей конфигурации без префикса. Если на целевом сервере настроен FEEDBACK_TABLEPREFIX, перед применением адаптировать имена таблиц под его значение. Миграции на игровой БД автоматически не выполняются.
3. При установке новой БД дополнительные таблицы входят в SQL/bandastation/bandastation_update.sql. Зарегистрировать версию 1.4 в schema_revision_220 согласно database_changelog.md.
4. Проверить SQL_ENABLED и подключение к БД, открыть этот worktree в VS Code и нажать F5. После изменения Rust-кода нужны пересборка библиотеки и перезапуск игры.

## Использование

В настройках персонажа кнопка с иконкой загрузки открывает «Портреты персонажа». Игрок видит свои изображения, предпросмотр и статус. Загруженный PNG, JPEG или WebP обрабатывается в фоновом Rust-потоке: большая сторона уменьшается до 1080 px, пропорции и прозрачность сохраняются, результат записывается в PNG. Маленькие изображения не увеличиваются. Ограничения: 10 МиБ, 24 миллиона пикселей, 30 секунд между попытками, до 10 PNG в pending; один Rust worker на сервер.

Администратор с правом R_ADMIN открывает Character Portrait Moderation в категории Game. Он видит портреты игроков и может одобрить либо отклонить ожидающий портрет. Решение, ckey проверяющего и дата записываются в БД. Повторное решение для уже проверенного изображения не допускается. Списки ограничены 500 последними записями.

Игрок выбирает одобренный портрет для слота, открытого при запуске панели, либо убирает выбор. Кнопка выбранного портрета подсвечивается. Выбор применяется при следующем создании персонажа. Данные в character_portrait_selections связаны с ckey и номером слота; маркер в JSON-профиле предотвращает наследование выбора новым персонажем после удаления слота. Чужие и не одобренные портреты не применяются.

Выбранный портрет показывается в окне «Раскрыть описание» вместо динамического превью персонажа. Картинка ограничена размерами контейнера и сохраняет пропорции. Если портрет не выбран, остаётся динамическое превью. При скрытом маской/шлемом лице или неизвестной внешности портрет не выводится. Скопированные DNA features сохраняют портрет персонажа.

## Хранение

    data/character_portraits/<ckey>/
      pending/<uuid>.png
      approved/<uuid>.png
      deny/<uuid>.png
      uploads/<uuid>.upload

Это диск машины, где запущен игровой сервер BYOND, а не компьютер игрока и не обязательно сервер БД. Путь data/character_portraits/ отсчитывается от рабочего каталога игрового процесса. При локальном запуске это локальный диск; на соседнем билде — его серверное хранилище. Абсолютный путь зависит от размещения и запуска сервера.

Временный исходник должен удаляться реализованным Rust-обработчиком. ckey, UUID и пути задаёт сервер; исходное имя файла используется только как метаданные. БД хранит UUID, владельца, исходное имя, размеры, статус, даты загрузки/проверки и модератора. Самих байтов изображений в БД нет: PNG находятся на диске игрового сервера. Таблица character_portrait_selections хранит выбор портрета для ckey и слота персонажа. Одной копии БД недостаточно для переноса картинок. Файлы, БД и JSON-профили следует сохранять в резервных копиях вместе.

Тестовые PNG, сохранённые до появления БД, автоматически не импортируются: для панели нужно загрузить их заново.

На Linux TGS нужна 32-битная libportrait_processor.so рядом с tgstation.dmb. Сборку библиотеки ещё нужно добавить; автоматическая установка из релиза не подключена. Библиотеку можно доставлять через GameStaticFiles TGS. Папка data уже отмечена как постоянная в .tgs.yml.

## Проверки

TGUI: bun test --cwd tgui packages/tgui/interfaces/CharacterPortraits.test.tsx, bun run --cwd tgui tgui:tsc и bun run --cwd tgui tgui:build. Rust-тесты и BYOND-проверку обработки нужно добавить вместе с реализацией библиотеки; эта ветка их не содержит.

Ручная проверка в игровом клиенте: загрузить изображение, одобрить его через админскую панель, выбрать для слота, создать персонажа и осмотреть его с другого клиента. Затем проверить скрытое лицо, другой слот, повторный вход и снятие выбора.
